# Reliability changes and validation

This refactor addresses the repository assessment against `45b400d`. It changes app-side orchestration and support code; the HeadsetControl submodule and its pinned revision are unchanged.

## Changes by risk area

| Area | Change | Main references |
| --- | --- | --- |
| Worker lifetime and shutdown | Asynchronous retirement orders queued restoration, cleanup, thread exit, and destruction. Replacement audio/display workers wait for the retiring thread to finish. No `QThread::terminate`, running-thread deletion, or blocking queued UI calls. A shared exit deadline handles stuck native drivers without racing library static destructors. | `workerthreads.*`, `panelengine.cpp`, audio/display/media managers |
| Qt singleton ownership | Explicit factories select one object; settings/logging outlive bridge teardown. QML engine destruction is synchronous, native windows use guarded pointers, and a failed QML load exits with failure. | singleton headers, `logmanager.cpp`, `usersettings.cpp`, `panelengine.*` |
| Logging | Mutex-protected 500-entry history exists before the debug pane opens. Coalesced snapshots bound event traffic and both QML views. | `logmanager.*`, `LogBridge.qml` |
| Audio COM | MTA initialization is balanced. The incompatible Vista policy-interface cast is removed. Callback targets are invalidated before cleanup. Partial enumeration failures retain the previous usable snapshot. | `audiomanager.*`, `policyconfig.h` |
| Audio identity and models | Core Audio instance IDs replace COM pointer IDs. Memory is sampled outside comparisons; surviving streams retain their rule index. Data-only updates preserve model indexes, and list models reject child rows. Old session caches are pruned. | `audiotypes.h`, `sessionindices.h`, `audiomodels.*`, `audiobridge.cpp` |
| Headset service | Independent from audio enablement. Desired settings cross threads as copied values; only successful writes are acknowledged. Retries are bounded and failures visible. One state snapshot replaces repeated cross-thread cache requests. | `headsetcontrolbridge.*`, `headsetcontrolmonitor.*` |
| Media | Late enablement is supported. Starts/stops are idempotent, late events are invalidated, COM/WinRT ownership is balanced, reads observe cancellation/deadlines, and failed manager acquisition or stale manager queries retry with backoff. Artwork uses bounded QImage decoding. | `mediasessionmanager.*`, `mediasessionbridge.*`, `nativeimage.*` |
| Display | A hidden top-level window receives display broadcasts and survives re-enumeration. Re-enumeration is queued. DDC values use native monitor ranges; only successful writes update per-monitor caches. WMI namespace, variant initialization, enumeration timeouts, and COM ownership are corrected. | `monitormanager.*`, `monitormanagerimpl.*` |
| Night Light | Reads validate registry type and known binary layouts. Unknown or truncated formats are never rewritten; opaque bytes are preserved. | `nightlightdata.h`, `monitormanagerimpl.cpp` |
| Background mute | Case-folded keys, initial focus seeding, no recursive focus signals, restoration after saving rule removal and during shutdown, and pruning of departed sessions. | `windowfocusmanager.*`, `audiobridge.cpp` |
| Shortcuts | Failed replacement bindings are reported and prior bindings restored when possible. Registration follows successfully saved settings; key/modifier changes are coalesced. Failed enablement saves retain the active bindings and switch state. Failed per-app saves restore the previous list and bindings; removals persist before unregistering, and the Add dialog stays open on failure. Destroying a capture pane releases shortcut suspension. | `keyboardshortcutmanager.*`, shortcut panes |
| Power | Capability queries and operations run on a worker. Shutdown/restart do not use force flags. Privilege and UEFI launch failures are checked and reported. Cached support properties include Modern Standby. | `powerbridge.*`, `PowerMenu.qml`, `Main.qml` |
| Persistence | Shared bounded/schema-checked reads and QSaveFile commits. Invalid existing JSON is copied to a unique `.corrupt-*` recovery file before replacement. Unreadable files are not overwritten. Settings values are bounded and QSettings errors reported. Language changes and downloaded-catalog reloads use the saved selection; failed saves retain the current translator and combo-box selection. Audio policy edits save candidate lists before publishing state or applying background mute changes; failures retain the previous policy, expose an error, and keep edit dialogs open. Repeated rename/icon edits no longer append duplicate entries. Duplicate lock creation and the unused communication-app settings copy are removed. | `jsonstore.*`, `usersettings.*`, `audiobridge.cpp` |
| Updater | Cancellation detaches replies before aborting. Translation batches own busy state and metadata, validate QM data, and commit atomically. Installer downloads stream to a unique staging directory, enforce size and SHA-256 from release metadata, and launch only after verification. | `updater.*`, `replybatch.h`, language bridge/pane |
| Build and release | Pinned HeadsetControl/vcpkg inputs, isolated dependency installation, explicit translation extraction, CTest release gate, and one verified build run for all release artifacts. Installer runtime version checks use the bundled redistributable. | `CMakeLists.txt`, workflows, `release_provenance.py`, `installer.iss` |

## Automated validation

The portable CMake test configuration covers malformed/truncated Night Light data and reversible transformations, plus provenance checks against wrong versions, source/dependency revisions, run IDs, missing assets, unexpected filenames, and altered artifacts.

With Qt development packages installed, `reliability_tests` additionally covers concurrent logging and bounded delivery, corrupt-settings recovery and failed writes, malformed schemas, stable stream indexes, Qt model invariants, synchronous/reentrant network cancellation, and cleanup/destruction on the owning worker thread. Windows builds require these tests. The tests do not invoke destructive power actions or real devices.

On Windows, the Qt suite also exercises per-app shortcut add, replacement, and removal against a locked policy file, checking retained JSON, UI notifications, native bindings, retry, and reload. It separately checks failure to create the first policy file. It also blocks the preferences file to check that rejected global shortcut changes retain native bindings, while successful enablement/key/modifier edits apply without a QML pane. The tests use isolated application-data and INI preference directories and do not write user preferences.

The full Windows build additionally tests all seven audio policy families against locked files: add, replace where applicable, and remove, with retained policy/model state, error reporting, retry, duplicate prevention, and reload. Initial audio policy creation failure is covered separately. Audio and headset workers remain disabled in these tests. A language regression test uses a compiled German catalog and a locked preferences file to check retained translations, download-triggered reload, and a successful retry to English.

## Remaining constraints and deliberate compatibility choices

- **Identical physical headsets:** the pinned library deduplicates VID/PID and resolves HID paths by model. Reliable physical-device selection needs a HeadsetControl fork and upstream pull request. This refactor does not change the submodule or claim to solve that limitation.
- **Native calls can still stall:** WMI enumerations and WinRT asynchronous reads have deadlines, but Windows RPC, DDC drivers, HID calls, and token revocation cannot all be interrupted safely. The UI remains separate. If cleanup exceeds the combined ten-second exit deadline, the process exits with failure and skips C++ static destructors. Pending device writes/restoration may not complete in that failure path.
- **Legacy stream rules:** existing rename/lock files still identify rules by original display name and stream index. Surviving streams no longer change index, but first-time assignment retains the previous memory-based policy (with a deterministic tie-break). Windows cannot infer the semantic role of an arbitrary stream. Recheck multi-stream application rules after application upgrades or process restarts; a future rule-schema migration needs explicit product semantics and compatibility fixtures.
- **Executable grouping:** existing settings continue to use executable basenames for compatibility. Separate installations with the same basename remain grouped. Moving to canonical executable identities needs a migration rather than silently dropping users' rules.
- **Night Light is undocumented:** only the two supported legacy layouts are accepted. A new Windows format disables this integration until reviewed; the Windows display settings remain the fallback.
- **Update compatibility:** automatic installation requires a release asset named `QontrolPanel_Installer.exe`, a valid SHA-256 digest, and a declared size. Older releases without those fields can still be downloaded manually. Successful installer launches retain their unique temporary directory so Windows can execute the installer after QontrolPanel exits.
- **Large policy/UI files:** native image conversion, persistent-file I/O, value models, stream indexing, and worker retirement are separated. AudioBridge and Main.qml remain substantial; further splitting should follow feature boundaries and preserve behavior under the tests instead of moving code mechanically.

## Windows validation before merging or releasing

1. Configure and build Release with the supported MSVC/Qt kit; run CTest and the INSTALL target. Launch only the installed executable.
2. Launch twice, including while the previous process is exiting. Confirm the existing panel opens and no headless instance remains. Quit with audio, media, display, and headset monitoring active.
3. Toggle audio, display, and media components repeatedly. Start with media disabled, then enable it. Keep headset monitoring enabled while disabling both audio components. Confirm no stale state returns from retired workers.
4. Add/remove audio sessions, switch default render/capture/communications endpoints, exercise per-app mute/volume, and verify legacy multi-stream renames/locks and ChatMix restoration. Check background mute on startup, focus changes, rule removal, and exit.
5. Validate headset polling and controls on real hardware, including disconnects, failed writes, recovery, charging, and battery notifications. Test modes validate presentation, not HID protocols.
6. Hot-plug external monitors; test mixed DDC/WMI displays, native brightness ranges, different queue delays, and partial failures. Confirm Night Light rejects unsupported data without writing it.
7. Close or crash the selected media source while artwork and transport requests are active. Verify restart, manual source selection, and cancellation on disable/exit.
8. Test shortcut conflicts, replacement rollback, capture-dialog closure and settings-page destruction. Check power capability presentation and reported failures using a safe test account; execute actual shutdown/restart/suspend only deliberately on a prepared machine.
9. Test offline/failed update checks, a corrupt installer payload, translation cancellation, navigating away during translation downloads, and reinstalling with an older/missing/current VC++ runtime. Verify the release workflow rejects a run from another branch or a mismatched artifact.
